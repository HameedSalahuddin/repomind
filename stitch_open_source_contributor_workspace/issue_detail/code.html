Fix route parameters parsing with special characters

adjust Open
person johndoe opened this issue 3 days ago
forum 4 comments
bug router
format_quote

When using Express v4.x, if a route parameter contains certain encoded special characters (like %2F for slash, or %2B for plus), the router fails to decode them correctly before passing them to the request handler, resulting in a 404 or incorrect parameter matching.

Steps to reproduce

  1. Create a basic express app with a parametrized route: app.get('/api/users/:id', ...)
  2. Send a request to /api/users/user%2Bname
  3. Check the value of req.params.id

Expected Behavior

The parameter req.params.id should be correctly decoded as user+name.

Actual Behavior

It remains encoded as user%2Bname, breaking downstream logic that expects the decoded string.

Code Snippet

const express = require('express');
const app = express();

app.get('/user/:id', (req, res) => {
    // req.params.id is not fully decoded if it contains %2B
    console.log(req.params.id); 
    res.send(req.params.id);
});

app.listen(3000);
